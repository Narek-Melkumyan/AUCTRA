# AUCTRA — Auction Marketplace (Demo Frontend)

A responsive, multi-category auction marketplace built with **TanStack Start**, **React 19**, **TypeScript**, **Tailwind CSS**, and **TanStack Router**. It is the web client of AUCTRA; the server is the NestJS API in [`../backend`](../backend), and the [project README](../README.md) covers the whole system. No mode accepts real payments.

It runs in one of two modes, set by `VITE_API_MODE` (copy `.env.example` to `.env.local`):

- **`api`** — talks to the AUCTRA backend at `VITE_API_URL`: real accounts and sessions, server-authoritative bidding with live Socket.IO updates, messaging, favourites, address book, admin and seller tools, and the AI assistant.
- **`demo`** (default) — the original in-browser simulation, with no backend. Screens that only make sense against the server (messages, favourites, address book, admin) say so instead of showing made-up data.

## Local development

Requirements: Node.js version compatible with the lockfile (Node 22 recommended) and npm.

```bash
npm ci
npm run dev
```

Open the localhost address printed by Vite. To run checks locally:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
npm run format:check
```

`npm run format` formats the tracked source (Prettier); review changes before committing. The frontend is configured for TanStack Start SSR and a Cloudflare-oriented Nitro build. `vite preview` can preview the production build.

## Source organization

```text
src/
  assets/                 Placeholder demo photographs
  components/
    account/              Shared account page layout
    ai/                   Assistant chat UI
    auction/              Auction UI widgets
    layout/               Header, navigation, shell and footer
    ui/                   Shared shadcn/Radix UI components
  hooks/                  Responsive hooks
  lib/
    api/                  REST + Socket.IO client for the backend (api mode)
    auctions.ts           Static listings, domain types, fee model
    auction-store.ts      Room state: live server feed (api) or simulation (demo)
    demo-session.ts       Browser-local profile and demo orders
    ai-mock.ts            Rule-based assistant using local data
    use-now.ts            Clock formatting and demo display timer
  routes/                 TanStack file routes (pages)
  services/
    types.ts              Backend-agnostic service contracts
    demo.ts               Demo implementation of those contracts
    index.ts              Service entry point
  test/                   Vitest regression tests
```

`src/routeTree.gen.ts` is **generated by TanStack Router**, not maintained manually.

## Current limitations

- Payments are always simulated: checkout records a demonstration order, with no payment processing, tax or shipping integration.
- In **demo** mode, sign-in is illustrative (a browser-local profile; no password is stored or checked), and timers, competing bids, chat, watcher counts and notifications are simulated on the client, so nothing is shared between devices. The assistant uses local matching rules and cannot place bids.
- Some marketing figures and help-center submissions are illustrative in both modes.

## Origin and development

The web client was first built with [Lovable](https://lovable.dev): the TanStack Start setup (`@lovable.dev/vite-tanstack-config` in `vite.config.ts`), the shadcn/Radix UI components and the original in-browser demo come from that project, and `src/lib/lovable-error-reporting.ts` still forwards runtime errors to Lovable's preview tooling when it is present (it does nothing elsewhere).

On **22 November 2026** the Lovable project's GitHub sync was disconnected. Lovable no longer reads from or writes to this repository, and the Lovable editor is not part of the workflow: AUCTRA is developed independently with [Claude Code](https://claude.com/claude-code) and GitHub, with the web client in `frontend/` and the API in `backend/`. Make every change in this repository, run the checks above, and open a pull request into `main`.

## Security

Do not commit `.env`, API keys, passwords, payment-provider secrets, or other sensitive data. `.env.example` contains only a safe demo configuration.
